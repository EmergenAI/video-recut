# Render

Read this when setting up rendering on a machine, rendering a draft or the final film, handling a
failed render, or checking the delivered file. [The composition page](../4-compose/page.md) owns what
the page must contain; [Review](review.md) owns judging what a render shows.

The composition page and its materials are the work; a render evaluates the whole page over the
film's duration and encodes the result. HyperFrames opens the page in a pinned headless Chrome,
seeks the paused timeline frame by frame across several browser workers, captures each frame,
encodes the picture with FFmpeg, mixes every `<audio>` element and muxes both into one file.

## Prepare once

On a new machine, from the Skill folder (`<skill>` = the folder holding SKILL.md):

```bash
cd <skill>/scripts && npm install                       # Node >= 22; installs HyperFrames and GSAP
node <skill>/scripts/render.mjs doctor                   # Node, ffmpeg, ffprobe, dependencies, Chrome
node <skill>/scripts/render.mjs prepare-browser          # Chrome Headless Shell 152.0.7928.2
```

`doctor` prints `ok` or `MISS` per requirement with what to do about each miss.
`prepare-browser` installs the one browser build the renderer is tested with into
`~/.cache/hyperframes/chrome`; it does nothing if already installed. When the official download is
slow or blocked, pass a mirror of the Chrome for Testing storage with `--mirror <base-url>`
([Networks, mirrors and caches](../1-setup/machine.md#networks-mirrors-and-caches)).
[Install the render tooling](../1-setup/machine.md#install-the-render-tooling) and
[Chrome Headless Shell](../1-setup/machine.md#chrome-headless-shell) cover installation problems.

Once per production, create the composition folder at the canvas size:

```bash
node <skill>/scripts/render.mjs init composition --width 1080 --height 1920
```

It writes `composition/index.html` from the page template, copies GSAP to `composition/vendor/` and
creates `composition/assets/`. It refuses to overwrite an existing page. `--id` changes the
composition id (default `main`); the timeline registration key must match it.

## Draft and final renders

```bash
node <skill>/scripts/render.mjs lint composition
node <skill>/scripts/render.mjs render composition renders/draft.mp4 --quality draft
node <skill>/scripts/render.mjs render composition renders/final.mp4 --quality standard
```

| `--quality` | Encoder setting | Use |
| --- | --- | --- |
| `draft` | x264 `ultrafast`, CRF 28 | Every review pass: layout, timing, captions, sound |
| `standard` (default) | x264 `medium`, CRF 18 | The deliverable |
| `high` | x264 `slow`, CRF 15 | Fine gradients, dense text or footage that bands or blocks at `standard` |

A draft skips the delivery checks and is never a deliverable; `standard` and `high` are deliverables
and run them ([Delivery checks](#delivery-checks)). Quality changes only the encoding; the captured
frames are the same. `--fps` sets the frame rate
(default 30). A draft at `--fps 15` captures half the frames for a faster rough pass; timing is
written in seconds, so nothing on the page changes, but motion looks coarser. Render the deliverable
at the frame rate the Brief asks for.

`--workers` sets the number of parallel browser workers (default 4). More workers help only while
the machine has cores and memory for them; above 4 the renderer warns about the default Node heap.
Lower it on a small machine or when renders fail from memory.

**There is no partial-range render.** Every render covers the whole film. To look at one passage,
render a draft of the whole film and read that passage in frames and grids
([Evidence: frames and grids](review.md#evidence-frames-and-grids)):

```bash
node <skill>/scripts/render.mjs frames renders/draft.mp4 renders/handoff.png --at 7.6,7.8,8.0,8.2 --width 360
node <skill>/scripts/render.mjs grid renders/draft.mp4 renders/grid.png --every 1
```

When the user needs a short clip with sound, cut it from the draft:
`ffmpeg -ss 7 -to 12 -i renders/draft.mp4 -c:v libx264 -c:a aac renders/passage.mp4`.

**Progress.** Lint runs first and prints its findings. The render then prints its stage and frame
count at each step (compiling, extracting video frames, processing audio, capturing frame N/M with
the worker count, encoding, assembling) and finally the file size, frame rate, quality and elapsed
time. A 13-second portrait film took about 20–30 s as a draft on a desktop machine; footage-heavy
pages take longer while video frames are extracted. Tell the user the current stage and meaningful
progress for long renders, and keep working on anything that does not depend on the result.
`--verbose` shows the engine's full trace.

**Media is not regenerated by a render.** A render reads the files already in `composition/`. Layout,
caption, timing and mix changes need only another render; never regenerate images, video or speech
for a composition change. When speech changes, re-take only the affected segment, rebuild the
timeline and render again.

## Delivery checks

Every render except `--quality draft` is a deliverable. Before rendering, it runs the
preflight in `check.mjs` against the production's `plan.json` (beside `composition/`) and refuses to
render when a check fails. Run the preflight alone while fixing:

```bash
node <skill>/scripts/render.mjs check composition
```

Each line reads `ok`, `ok*` (a failure accepted through a user-approved deviation) or `FAIL`, with the
check id and what to do. After encoding, the render compares the film's length with
`targetDuration`, allowing the larger of 1.5 s and 10%:

- **Within it:** `<out>.report.json` is written beside the film, with every check and deviation.
- **Outside it:** the film is renamed `<out>.REJECTED.mp4` (for `renders/final.mp4`,
  `renders/final.REJECTED.mp4`), kept for review, and the command fails.

Only a film with its report is delivered. [The production plan](../2-plan/production-plan.md) lists
the checks and how to fix each; never edit `plan.json` just to pass one.

## When a render fails

Read the first error; the rest often follows from it.

- **`delivery checks failed`.** Fix what each `FAIL` line names
  ([Delivery checks](#delivery-checks)); a draft still renders for review meanwhile.
- **`the film does not match plan.json`.** The length check failed and the file was renamed
  `.REJECTED`; realize the planned length, or agree a change with the user.
- **`lint errors block rendering`.** The lint findings above it name each problem with a fix line.
  Fix them in the page ([Lint findings that matter](../4-compose/page.md#lint-findings-that-matter)).
  `--allow-lint-errors` renders anyway for diagnosis only; never deliver that file.
- **Missing assets.** `missing_local_asset` and `audio_src_not_found` name the path the page asked
  for. Paths are relative to `composition/index.html`, and the file must be inside `composition/`.
  For speech, `timeline.mjs` warns when a segment's audio lies outside the composition folder;
  move the file and rebuild. A generated file still being produced is not there yet:
  `bibei.mjs status --dir composition/generated` shows it.
- **Fonts.** `font_family_without_font_face` blocks until every family has an `@font-face`. A
  `local()` name that does not exist on the machine is not an error: the text silently falls back
  to another face. Read a frame with text in it and compare with the intended face; use the full
  font name (as in the font's properties) or bundle the file.
- **`Chrome Headless Shell … is not installed`.** Run `render.mjs prepare-browser`. If the download
  fails, see [Chrome Headless Shell](../1-setup/machine.md#chrome-headless-shell).
- **`dependencies are not installed`.** Run `npm install` in `<skill>/scripts`.
- **`render failed at <stage>: <message>`** followed by `browser console:`. The console tail shows
  errors thrown by the page. Typical causes: `window.TIMELINE` undefined (the `timeline.js` script tag
  is missing, misplaced after the page script, or the file was not built); a typo in the page script;
  a timeline registered under the wrong id; an image that cannot be decoded; a video codec the
  browser cannot play (convert it to H.264 MP4 with [Conform footage and audio](../3-materials/media-prep.md#conform-footage-and-audio)).
  Re-run with `--verbose` when the stage alone does not explain it.
- **The render succeeds but the picture is wrong.** Blank frames, a frozen video, a caption stuck on
  screen or the wrong length are page problems, not render problems: check the timeline registration,
  the final `tl.set({}, {}, DURATION)`, nested timed media and exit sets, then look at frames.
- **Out of memory or a crashed worker.** Lower `--workers`, and close other heavy applications.

Keep failed drafts out of the deliverable folder; name them for the pass (`renders/draft-2.mp4`)
when comparing before and after a change.

## Deliverables

The default deliverable is an MP4: H.264 video (`yuv420p`) at the composition's canvas size and the
chosen frame rate, with AAC stereo audio at 48 kHz. That plays on every platform the user is likely
to name. `--format webm` (VP9) and `--format mov` (ProRes 4444) exist for a picture with an alpha
channel, such as an overlay for another editor; they have not been verified in this Skill, so render
a short test and check the alpha with ffprobe (`pix_fmt` of `yuva420p` or `yuva444p10le`) before
promising one.

Before delivering, check the file itself:

```bash
ffprobe -v error -show_entries stream=codec_name,codec_type,width,height,r_frame_rate,pix_fmt,sample_rate,channels:format=duration -of compact renders/final.mp4
ffmpeg -hide_banner -i renders/final.mp4 -af ebur128=framelog=quiet -f null - 2>&1 | grep -A3 "Integrated"
```

- **Streams**: one `h264` video at the intended width, height and frame rate, `yuv420p`; one `aac`
  audio stream. A missing audio stream means no `<audio>` reached the film.
- **Duration**: the timeline's `duration` (within a frame). Shorter means the timeline ends early;
  longer means an extra tween or `tl.set` extends it.
- **Loudness**: integrated LUFS and true peak where the Brief or platform expects them
  ([Levels, fades and ducking](../4-compose/sound.md#levels-fades-and-ducking)).
- **Picture**: a grid of the whole final render and full-size frames of the text-heavy moments,
  read as in [Review](review.md).
- **Sound**: listen to the whole file once, start to end, at normal volume.

If you cannot play audio, verify the sound objectively instead, and tell the user it has not been
listened to and ask them to play it once:

```bash
ffprobe -v error -select_streams a -show_entries stream=codec_name,sample_rate,channels -of csv=p=0 renders/final.mp4
ffmpeg -hide_banner -i renders/final.mp4 -af loudnorm=print_format=summary -f null - 2>&1 | grep -E "Input (Integrated|True Peak)"
ffmpeg -hide_banner -i renders/final.mp4 -af silencedetect=noise=-30dB:d=0.2 -f null - 2>&1 | grep -oE "silence_(start|end): [0-9.]+"
```

An audio stream is present; integrated loudness sits around −16 to −14 LUFS for social video with
true peak below −1 dBTP (a peak at or above 0 dBTP means clipping); and the silences fall between
the segments of `timing/timeline.json`, not inside one. A music bed raises the floor: set `noise`
just above it (−30 dB here) so pauses under the music still register.

**File size.** `standard` quality produces high bitrates (about 17 Mb/s at 1080×1920, 50 MB for
23 s). For an upload limit, re-encode and check the result by frames:

```bash
ffmpeg -i renders/final.mp4 -c:v libx264 -crf 23 -preset slow -pix_fmt yuv420p -c:a copy -movflags +faststart renders/final-small.mp4
node <skill>/scripts/render.mjs frames renders/final-small.mp4 renders/final-small-check.png --at 2,10 --width 1080
```

Raise `-crf` for a smaller file (each +6 roughly halves it); look at text-heavy frames at full size.

Before delivering, confirm that the words heard are the words in the captions: listen through, or
when you cannot, use the objective checks above and tell the user. Deliver the file from `renders/`
together with its `.report.json`, with the important choices and any material limitations explained
([The finished work](review.md#the-finished-work)).
